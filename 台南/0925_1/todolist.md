## 1. AI 執行規則

### 1.1 需求優先順序

1. 使用者當次對話中的明確要求。
2. PRD.md 已確認的產品需求與 MVP 決策。
3. 本文件的任務順序、驗收條件與技術建議。
4. 專案現有程式碼、測試與 Apple 平台慣例。

若 PRD.md 與本文件衝突，以 PRD.md 為準，並先更新本文件再繼續。不得自行擴大 MVP 範圍，也不得把 P2 功能加入 P0/P1。

### 1.2 每次工作循環

AI 每次執行任務時必須依序完成：

1. 閱讀 PRD.md、本文件及相關程式碼。
2. 檢查 Git 工作目錄，保留使用者既有且不相關的變更。
3. 找到第一個尚未完成、沒有阻礙的任務。
4. 說明本次任務及不會處理的範圍。
5. 只實作完成該任務所需的最小變更。
6. 執行任務列出的自動化或人工驗證。
7. 檢查錯誤、空資料、深色模式及基本無障礙。
8. 驗證成功後才將待辦從 [ ] 改為 [x]。
9. 更新「目前執行狀態」及「執行紀錄」。
10. 回報完成項目、修改檔案、驗證結果、限制及下一任務。
11. 若目前 Phase 的全部任務已完成，必須進入人工驗收流程並停止工作，不得接著執行下一個 Phase。

### 1.3 修改範圍

- 一次以一個任務 ID 為主；只有緊密相依的小任務可一起完成。
- 一次最多完成一個 Phase，嚴禁在同一次連續執行兩個 Phase。
- 不得因重構順便加入 PRD 未要求的功能。
- 不得任意修改 PRD.md；需要改需求時先向使用者說明。
- 不得修改或提交 xcuserdata、個人簽章設定及本機 UI 狀態。
- 不得提交、推送、建立分支或發布 TestFlight，除非使用者明確要求。
- 新增第三方套件前，先確認 Apple 原生 API 無法合理完成，並取得使用者同意。
- MVP 優先使用 SwiftUI、SwiftData、AVFoundation、UserNotifications、Charts。
- UI 文案使用繁體中文；型別與變數使用清楚的英文命名。
- 日期運算使用 Calendar 並考慮時區與跨日，不把一天寫死為固定秒數。
- 授權未確認的單字、例句、音檔及圖片不得放入正式字庫。

### 1.4 狀態標記

- [ ] 尚未開始
- [x] 已完成且驗證通過
- ⏸ 等待使用者決策或外部條件
- 🚧 正在進行；同時最多一項

任務受阻時不可勾選完成，必須在「目前阻礙」記錄原因與需要的決策。

### 1.5 Phase 人工驗收閘門

每一個 Phase 都是強制停止點。AI 完成該 Phase 的所有任務與驗證後，必須依照以下流程：

1. 將當前 Phase 狀態更新為「等待使用者檢查」。
2. 整理本 Phase 的完成項目、修改檔案、建置與測試結果。
3. 提供使用者可實際檢查的畫面、操作路徑及驗收清單。
4. 清楚列出尚未解決的問題、限制及任何與 PRD 的差異。
5. 停止所有程式修改，不得預先開始下一個 Phase。
6. 等待使用者檢查並回覆。

使用者回覆後，依下列規則處理：

- 使用者明確表示「執行下一個 Phase」、「進入下一階段」或其他同等意思時，才能將目前 Phase 標記為「已核准」，並開始下一個 Phase。
- 使用者提出問題或要求修正時，只能修正目前 Phase 的範圍；修正及驗證完成後必須再次停止，重新等待檢查。
- 使用者只說「看起來不錯」、「收到」或詢問問題，但沒有明確要求繼續時，不可自行進入下一個 Phase。
- 即使時間與上下文充足，也不得因為「順便」或「可以繼續」而跨過驗收閘門。
- 最後一個 Phase 完成後，同樣需要等待使用者最終確認，不得自行上傳或送審。

Phase 完成時，AI 的最後一句應為：

> Phase N 已完成並停止。請檢查以上結果；確認沒有問題後，請回覆「執行下一個 Phase」。

## 3. 建議專案結構

以下結構應隨任務逐步建立，不要一次建立未使用的空檔案：

~~~text
0925_1/
├── App/
├── Models/
├── Data/
│   └── Resources/
├── Services/
├── Features/
│   ├── Onboarding/
│   ├── Home/
│   ├── Study/
│   ├── Quiz/
│   ├── Completion/
│   ├── Library/
│   ├── Statistics/
│   └── Settings/
├── DesignSystem/
└── Assets.xcassets/
~~~

架構原則：

- View 只處理顯示與互動，不承擔複習排程及統計運算。
- 複習排程、每日任務、統計、語音與通知各自封裝成可測試的 Service。
- SwiftData Model 負責持久化；功能邏輯不得散落在各個 View。
- 時間相關 Service 可注入「現在時間」，測試不依賴真實日期。
- 避免過度抽象；沒有第二個使用情境時，不先建立複雜 protocol。

## 4. Definition of Done

任務符合以下條件後才能標記完成：

- 符合 PRD.md 與該任務驗收條件。
- Debug 組態建置成功。
- 新增或修改的核心邏輯具有單元測試。
- 既有測試全數通過，且未刪除或弱化有效測試。
- 沒有新增警告、明顯崩潰路徑或未處理的資料錯誤。
- 畫面至少檢查小尺寸 iPhone、一般尺寸 iPhone、深色模式及放大字體。
- 主要互動元件有適當的 VoiceOver label、hint 或 value。
- 學習結果立即持久化，重開 App 後仍存在。
- 核心學習流程可離線使用。
- 本文件的狀態、驗證結果及執行紀錄已更新。

# Phase 1：資料層與核心學習引擎

> **人工驗收閘門：**完成本 Phase 後必須停止，等待使用者檢查並明確要求「執行下一個 Phase」。

## 目標

先完成可測試的資料結構、種子資料及複習邏輯，再串接 UI。

- [ ] **WF-010｜定義學習 Enum**
  - 狀態：new、learning、reviewing、mastered。
  - 自評：forgot、uncertain、remembered。
  - 定義必要程度及詞性型別，避免 magic string。
  - 驗收：可持久化且有 raw value 單元測試。
  - 相依：WF-006。

- [ ] **WF-011｜建立 Word 與 Deck Model**
  - 欄位依 PRD：原文、音標、詞性、繁中釋義、英中例句、難度、標籤。
  - 定義唯一值、顯示順序及 relationship。
  - 驗收：可在 in-memory ModelContainer 新增、查詢及刪除。
  - 相依：WF-010。

- [ ] **WF-012｜建立 LearningProgress Model**
  - 包含熟悉度、答對／答錯、最後及下次複習日期、收藏狀態。
  - 每個 Word 只能對應一份有效進度。
  - 驗收：資料重新查詢後仍正確。
  - 相依：WF-011。

- [ ] **WF-013｜建立 UserSettings Model**
  - 每日新字預設 10，並包含提醒、發音、所選字庫及 Onboarding 狀態。
  - 第一次啟動只建立一份設定。
  - 驗收：預設值與持久化有測試。
  - 相依：WF-011。

- [ ] **WF-014｜建立 StudySession 與 ReviewEvent Model**
  - 記錄開始／結束、學習字數、正確數及作答事件。
  - 只存 PRD 指標所需資料，不存敏感個資。
  - 驗收：可計算單日完成量與正確率。
  - 相依：WF-012。

- [ ] **WF-015｜建立正式、Preview 與測試用 ModelContainer**
  - App 使用持久化 Container；Preview、測試使用 in-memory Container。
  - 初始化錯誤需可理解，不以 fatalError 處理一般錯誤。
  - 驗收：三種環境皆可建立 Container。
  - 相依：WF-011～WF-014。

- [ ] **WF-016｜建立 JSON Schema 與 20～30 字測試字庫**
  - 涵蓋所有必要欄位及多個主題。
  - 清楚標示為開發資料，不假裝是正式 500 字。
  - 驗收：可解碼、ID 不重複、必要欄位不為空。
  - 相依：WF-011。

- [ ] **WF-017｜實作 SeedDataImporter**
  - 首次啟動匯入，重開不得重複建立單字。
  - 失敗時提供可理解錯誤，不留下重複或半套資料。
  - 驗收：連續匯入兩次後筆數不變。
  - 相依：WF-015、WF-016。

- [ ] **WF-018｜實作 ReviewScheduler**
  - 忘記：10 分鐘；模糊：1 天。
  - 第 1 次記得：3 天；第 2 次：7 天；第 3 次以上先採 14 天。
  - 答對 3 次且最近一次間隔至少 7 天時標記 mastered。
  - 驗收：各分支、跨日、時區及夏令時間邊界都有測試。
  - 相依：WF-010、WF-012。

- [ ] **WF-019｜實作 DailyStudyPlanner**
  - 先排到期複習字，再依目標加入新字。
  - 同一輪不可無故重複；「忘記」可排入當日稍後再次出現。
  - 處理無新字、無複習字及全部完成狀態。
  - 驗收：能正確建立「10 個新字＋15 個複習字」任務。
  - 相依：WF-017、WF-018。

- [ ] **WF-020｜實作 SpeechService**
  - 使用 AVSpeechSynthesizer 播放單字與例句。
  - 停止前一次發音，避免快速點擊重疊。
  - 語音不可用時不得影響學習進度。
  - 驗收：模擬器無語音時不崩潰。
  - 相依：WF-006。

### Phase 1 完成條件

- 小型內建字庫可離線建立每日任務。
- 複習日期、熟悉度及掌握狀態有完整測試。
- App 重開後資料不重複、不遺失。

## 6. 建置與驗證指令範本

執行前先以 xcodebuild -list 確認 scheme 名稱。

~~~bash
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer \
xcodebuild \
  -project 0925_1.xcodeproj \
  -scheme 0925_1 \
  -configuration Debug \
  -destination 'generic/platform=iOS Simulator' \
  CODE_SIGNING_ALLOWED=NO \
  build
~~~

測試前查詢本機可用 Simulator，再把 SIMULATOR_NAME 換成真實名稱：

~~~bash
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer \
xcodebuild \
  -project 0925_1.xcodeproj \
  -scheme 0925_1 \
  -destination 'platform=iOS Simulator,name=SIMULATOR_NAME' \
  test
~~~

AI 不可把範本中的 SIMULATOR_NAME 原樣當成可執行值。
